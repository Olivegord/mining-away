# Independent gameplay, authority and parity review

Baseline reviewed: `736543b75a62026d2d7bddb5be20b6f9414d38d7`. The source was inspected independently of the map, UI and effects edits. This is a code and executable-logic review, not a Roblox Studio or multiplayer playtest.

## Finding and repair

**P1: an initially blocked safe field could remain empty for the whole server session.** `seedField` stopped when a bounded set of 18 resource placement attempts failed, but scheduled no retries. Safe fields do not pass through an encounter reset, so a temporary obstruction or a crowded first placement could permanently remove all or part of their ore budget. This risk matters especially when the map geometry is being rebuilt.

The authoritative seeding path now adds a deferred retry token for each missing node-budget unit. A geode already consumes five units, so a partial geode seed queues only the remaining capacity. Existing bounded sampling and per-field respawn logic process those tokens; no client selects a reward, resource position or spawn seed. When an entire due group is still blocked, the group shares a two-second backoff rather than causing 18 raycasts per missed slot at successive snapshot ticks. The actual bundled server was executed with a Roblox API double in four new tests: all placements initially blocked then unblocked, one crystal placed before a block, sustained blocking with a bound on sampling attempts, and one five-unit geode placed before a block. Each test checks recovery and that live budget plus pending retry tokens equals configured field capacity.

An additional bounded cosmetic snapshot contract publishes the live `CombatTargetId` and the short-lived `ForkTargetId` / `ChainTargetId` only for authoritative target/proc state. Existing world-position attributes remain. IDs are blanked on release, expiry, death and target loss; they do not confer damage or reservation authority. The actual-server suite checks the target lifecycle and successful secondary procs.

**P1: a rapid same-server reconnect could be dropped while the previous Player was still saving.** The old `addPlayer` returned whenever the prior user profile or initial load was still present. If a replacement `PlayerAdded` arrived during the yielding leave/release, the event was discarded and no later load was scheduled. The actual server reproduced the lost-fleet state using an UpdateAsync test hook.

The server now retains at most one pending replacement Player per user and loads it only after the old lease has been safely released, including when `PlayerAdded` arrives before `PlayerRemoving` or after an abandoned initial load. Lost final-release responses are reconciled; a failed release exposes an unavailable status and never creates defaults. A subsequent reconnect first reconciles/releases any locally orphaned session rather than staying permanently blocked by the old local lease. Five actual-server tests cover the two join/leave orderings, abandoned load, committed release with lost responses, failed release and later recovery while preserving the old credits and owned drone.

**P1: autosave interrupted active mining.** The previous busy check released a drone's target, slot and warmup on each yielding save. The save boundary now pauses damage while retaining the reservation and offsets the warmup start by elapsed simulation time; the unchanged job resumes after the save. UpdateAsync-hook tests of routine autosave during warmup and during an already firing beam, plus a lost response, run the production drone step while the save is in progress and checks the target, slot, ore, HP and warmup clock. Unhealthy sessions still fail closed. Replicated warmup timestamps permit observers to render charge without authorizing damage.

**Assignment consistency.** Repeated field commands preserve an existing job, including its warmup, in the legacy and acknowledged protocols; eligible idle drones join mineable fields without joining a locked assault. A specific-drone assignment validates the current run, owned living drone and life, command range, cleared gate, resource readiness and an available server-owned slot before it releases the old job. Slot counts are replicated on change and acknowledged privately to the requesting PlayerGui. Tests cover a busy target, stale run, stale life, foreign drone, guarded resource, same-target replay, successful retarget and cancellation; these are API-double tests, not proof of actual network replication.

## Executed checks

- **57 actual-server integration checks** passed using the official Luau CLI against Roblox API/data-store doubles, including a one-Blue starter, saved three-choice offers, exact target and free reprint, prestige into two permanent drones, repeat/retry/stale requests, co-op and outsider entitlements, ten weak resets, deferred wins during a save, uncertain commit recovery, reconnect interleavings, strict one-stud mining, geode budget and the new blocked-start recovery.
- **35 encounter/resource rule, 18 profile, 27 card, 28 persistence and six progression-model checks** passed. The logic checks exercise the same repository modules; they are not replacement implementations.
- The baseline ten-seed model reports median first pack **63.68 seconds**, first prestige **458.43 seconds** and second prestige **810.55 seconds**. These are deterministic estimates under the documented route/combat/card heuristic, not observed player timings. Re-run after final map or balancing changes because travel assumptions can change.

The independent audit also checked the ownership/run/life predicates and the shared encounter's full-defense reset, transaction staging/reconciliation, preview isolation, world-token clearance and original-equation mining station. No additional confirmed P0/P1 authority bypass was found in the reviewed paths. That is not proof against all possible defects.

## Required outstanding evidence

No real Studio engine, live networked clients or live DataStore were available for this review. The visual art director's independent final veto requires current-candidate in-motion evidence: normal and close viewpoints; moving muzzle/impact alignment through shrink/tilt; telegraph and transition quality; no clipped beams, opaque particles, or hovering/buried props; busy scenes; low/high graphics and multiple viewport sizes. A source test or baseline screenshot cannot satisfy it. Real playtime, six-drone performance and crash/restart persistence also remain acceptance work.
